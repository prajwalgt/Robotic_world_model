# G1 Data Collection Guide

## How `state_action_data_0.csv` is collected

The CSV is generated by running a policy in **Isaac Sim during online pretraining** and logging the observation groups each step. There is **no CSV export code** in the repo — the original ANYmal D data was created externally.

The offline imagination training (`train.py --task unitree_g1_flat`) needs initial states to branch rollouts from. The CSV provides ground-truth simulator transitions for this purpose.

---

## ANYmal D CSV structure (66 columns, 10,000 rows)

| Group | Dims | Contents |
|---|---|---|
| `system_state` | 45 | base_lin_vel(3) + base_ang_vel(3) + projected_gravity(3) + joint_pos_rel(12) + joint_vel_rel(12) + joint_torque(12) |
| `system_action` | 12 | last_action(12) |
| `system_extension` | 0 | disabled |
| `system_contact` | 8 | thigh_contact(4) + foot_contact(4) |
| `system_termination` | 1 | base_contact(1) |

## G1 CSV structure (160 columns, 10,000 rows)

| Group | Dims | Contents |
|---|---|---|
| `system_state` | 120 | base_lin_vel(3) + base_ang_vel(3) + projected_gravity(3) + joint_pos(37) + joint_vel(37) + joint_torque(37) |
| `system_action` | 37 | last_action(37) |
| `system_extension` | 0 | TBD |
| `system_contact` | 2 | foot contacts (left_ankle_link + right_ankle_link) |
| `system_termination` | 1 | base_contact(1) |

## How to collect data for G1

### Prerequisites

- Isaac Sim 4.5.0 + Isaac Lab 2.1.0 installed
- G1 pretrain task registered (e.g. `Template-Isaac-Velocity-Flat-Unitree-G1-Pretrain-v0`)

### Steps

1. **Write a `collect_data.py` script** that:
   - Loads the G1 pretrain Isaac Lab environment
   - Runs a policy (random or pretrained) for 10,000 steps
   - Each step, extracts from the observation dict:
     - `obs["system_state"]` (120 dims)
     - `obs["system_action"]` (37 dims)
     - `obs["system_contact"]` (2 dims)
     - `obs["system_termination"]` (1 dim)
   - Concatenates them column-wise into a single tensor per step
   - Saves with `pd.DataFrame.to_csv("state_action_data_0.csv", header=False, index=False)`

2. **Save the CSV** to `robotic_world_model/assets/data/state_action_data_0.csv`

3. **Verify dimensions match** `UnitreeG1FlatConfig.DataConfig` in `scripts/reinforcement_learning/model_based/configs/unitree_g1_flat_cfg.py`:
   - `state_idx_dict` expects indices [0:120] for state
   - `state_data_mean` / `state_data_std` are length 120
   - `action_data_mean` / `action_data_std` are length 37

4. **Test with offline training:**
   ```bash
   python scripts/reinforcement_learning/model_based/train.py --task unitree_g1_flat
   ```

### Multiple files

The data loader reads files sequentially (`state_action_data_0.csv`, `state_action_data_1.csv`, ...) until `batch_data_size` rows are loaded. Each file should have `file_data_size` rows (default 10,000). For G1 the default `batch_data_size` is 10,000 so one file suffices.

## Important notes

- **Isaac Sim is required** to collect this data — it cannot be generated without the physics simulator
- The data in the CSV is **not normalized** — normalization is handled by the `SystemDynamicsDataset` class in `train.py` using the `state_data_mean`/`state_data_std` values from the config
- The column order **must be**: state | action | extension | contact | termination
